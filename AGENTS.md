# Agent Guidelines — Whiteboard

This repository is a real-time collaborative infinite whiteboard powered by CRDT (Yjs), organized into two independent Git submodules.

All autonomous AI agents (Claude, Cursor, Copilot, ChatGPT, Devin, Antigravity, etc.) and human contributors must strictly follow the rules, conventions, and invariants documented here.

---

## Workspace Topology

- `backend/`: NestJS 11 dual-entrypoint service (REST API on port 3001, WebSocket Collab server on port 3002).
- `frontend/`: Next.js 16 (App Router) + React 19 + custom 2D Canvas Engine on port 3000.
- `docs/`: System architecture (`docs/architecture.md`), development guide (`docs/DEVELOPMENT.md`), testing guide (`docs/TESTING.md`), protocol spec (`docs/PROTOCOL.md`), ADRs (`docs/adr/`), and task backlog (`docs/tasks/`).
- `docker-compose.deps.yml`: Infrastructure services (PostgreSQL on 5442, Redis on 6379, MinIO on 9000/9001).
- `Makefile`: Unified task execution and verification harness.

## 🚫 Prohibited Comments & Documentation Standards

All codebase documentation and comments must adhere to professional engineering standards. The following comment styles are **strictly forbidden and will be rejected**:

### Unacceptable Comments:
1. **AI / Model Chatter**:
   - Never add comments referencing AI identity or user requests (e.g., `// Added as requested by user`, `// Generated by AI assistant`, `// Model response here`).
   - Source code must look like it was authored by a senior systems engineer.
2. **Commented-Out Dead Code**:
   - Never leave blocks of commented-out code (`// const oldWay = ...`).
   - Rely on Git history for code retrieval; dead code clutter degrades maintainability and causes agent hallucinations.
3. **Obvious & Redundant Noise**:
   - Never write comments that merely repeat what the code does (e.g., `// Returns user` before `return user;`, `// Loop over elements` before `for (const el of elements)`).
4. **Stale or Misleading Comments**:
   - If code changes, update or remove associated docstrings immediately. Stale comments are worse than no comments.
5. **Apologetic or Conversational Tone**:
   - Never use comments to apologize, explain difficulties, or chat with future readers.
6. **Anonymous TODOs**:
   - Never leave orphan `// TODO` or `// FIXME` without context or issue tracking. Prefer completing the work or documenting it in `docs/tasks/`.

### Acceptable & Encouraged Comments:
- **Mathematical Rationale**: Explaining non-obvious geometric formulas (e.g., LERP easing, Catmull-Rom spline tension, bounding-box transformations, coordinate conversion edge cases).
- **Protocol & RFC References**: Linking to CRDT convergence papers, W3C standards, or Yjs protocol specifications.
- **Architectural Warnings**: Documenting critical invariants (e.g., why a specific transaction origin tag is mandatory to prevent circular loops).
- **Public API TSDoc / JSDoc**: Clear parameter, return type, and throws descriptions on exported functions and classes.

## 🛑 Prohibited Code Smells & Antipatterns

The following code smells are strictly prohibited across both submodules:

### 1. Type Safety Violations
- **`any` and `as any`**: Strictly forbidden. Use `unknown`, generic parameters, or validate runtime payloads with Zod schemas.
- **`@ts-ignore` / `@ts-nocheck`**: Strictly forbidden. Resolve the underlying type mismatch or structural interface.
- **Unsound Type Assertions**: Avoid `x as SpecificType` without an accompanying runtime type-guard or schema parse.

### 2. Error Handling Smells
- **Swallowed Errors / Silent Catches**: Never write empty catch blocks (`catch (e) {}`). Always log, rethrow, or handle with explicit domain recovery.
- **Generic / Untyped Throws**: Never throw raw strings or generic errors (`throw "error"` or `throw new Error()`). In NestJS, use standard HTTP exceptions (`BadRequestException`, `NotFoundException`, `ForbiddenException`).
- **Unhandled Promise Rejections**: All async operations must be awaited or handled with proper `.catch()` error logging.

### 3. Architecture & Domain Smells
- **Mixing Screen and World Coordinates**: Never use raw mouse event offsets directly in element positioning. Always transform via `viewport.screenToWorld()` and `viewport.worldToScreen()`.
- **Desynchronized Spatial Index**: Never mutate an element's position, size, or existence without updating the R-Tree spatial index (`SpatialIndex` / RBush).
- **Untagged CRDT Mutations**: Never mutate a shared Yjs `Y.Doc` without an explicit transaction origin (e.g., `store.localOrigin`). Failing to tag transactions causes infinite echo loops between UndoManager, WebSocket broadcasts, and persistence workers.
- **Binary Assets over WebSockets**: Never transmit raw file bytes (images, PDFs) over the real-time WebSocket channel. Binary assets MUST be uploaded directly to S3/MinIO via Presigned PUT URLs.
- **Bypassing Zod Validation**: Never apply external deltas directly to canonical documents without validating through the authoritative server Shadow Document (`ElementDataSchema`).
- **Stateless/Stateful Boundary Pollution**: Never store in-memory room docs in `main.api.ts`, and never expose HTTP REST endpoints (`/v1/*`) on `main.collab.ts`.
- **N+1 Database Queries**: Ensure Prisma queries fetch relational data using proper `include` or explicit batching, and maintain indexes on foreign keys (`board_id`, `user_id`, `token_hash`).
- **Non-Standard Database Schema Identifiers**: Never define PostgreSQL tables or columns in PascalCase or camelCase. All relational tables and columns must use `snake_case` (`table_name`, `column_name`) mapped via Prisma `@@map("table_name")` and `@map("column_name")`.

## 📦 Commit Message Standardization

All commits across the root repository and both submodules must strictly adhere to the [Conventional Commits](https://www.conventionalcommits.org/) specification, enforced by Husky and Commitlint:

```
<type>(<scope>): <subject>

[optional body]

[optional footer(s)]
```

### Format Rules:
- **Type**: Must be one of `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `chore`.
- **Scope**: Lowercase noun describing the module or feature (e.g., `canvas`, `auth`, `collab`, `studio`, `deps`, `readme`).
- **Subject**: Imperative mood, lowercase, no trailing period, maximum 72 characters.
  - Good: `feat(canvas): implement magnetic snap alignment guides`
  - Good: `fix(auth): prevent race condition in atomic refresh token rotation`
  - Bad: `Added new tool.` (not imperative, capitalized, has trailing period)
  - Bad: `WIP: working on stuff` (unstructured)

### Submodule Commit Protocol:
1. Always commit inside the modified submodule repository first (`backend/` or `frontend/`).
2. Then commit the updated submodule commit pointer in the root repository:
   ```bash
   git add backend frontend
   git commit -m "chore: update submodule pointers"
   ```

## 🏛️ Architectural Invariants (Must Never Violate)

| Area | Invariant Rule | Rationale |
| :--- | :--- | :--- |
| **Backend API** | Never hold in-memory board state in `main.api.ts` | The REST API must remain strictly stateless and horizontally scalable behind load balancers. |
| **Collab Server** | Never expose HTTP REST endpoints (`/v1/*`) on `main.collab.ts` | The Collab Server is exclusively a stateful WebSocket server (`ws://localhost:3002/collab`). HTTP is reserved strictly for infrastructure probes (`/health`, `/metrics`). |
| **CRDT Schema** | Every element MUST contain valid `createdBy`, `id`, `type`, `x`, `y`, `w`, `h`, `z`, and `style` (`fill`, `stroke`, `strokeWidth`, `opacity`) | The Collab Server maintains a Zod shadow doc validator. Incomplete elements will be rejected and dropped. |
| **Transactions** | Always tag local CRDT edits with distinct origin (e.g. `store.localOrigin`) | Prevents infinite loop echoes between local UndoManager, WebSocket updates, and persistence worker. |
| **Canvas Coordinates** | Strictly separate Screen Coordinates (pixels relative to canvas element) from World Coordinates (infinite space) | Rendering and hit testing require explicit transformation through `viewport.screenToWorld()` and `viewport.worldToScreen()`. |
| **Spatial Index** | Any addition, deletion, or geometry modification of an element MUST update `SpatialIndex` (RBush) | Culling and hit-testing rely on the R-Tree index staying synchronized with `repository.getAllElements()`. |
| **File Storage** | Assets (images/files) MUST be uploaded directly via S3 Presigned PUT URLs | Binary asset payloads must never be transferred across the real-time WebSocket collab channel. |
| **Contracts** | `backend/src/shared/` is the single source of truth; never edit `frontend/src/shared/` directly | Avoids contract divergence between server and client. |
| **Database Schema** | All PostgreSQL tables and columns MUST use `snake_case` (`table_name`, `column_name`) | Keeps database conventions standard and portable across SQL engines while allowing idiomatic TypeScript in Prisma models via `@@map` and `@map`. |

## 🔍 Agent Troubleshooting & Diagnostics

- **Sandbox Read-Only `/index.lock`**:
  If a git command in root fails with `Unable to create '.git/index.lock': Read-only file system`, retry that specific git command outside the sandbox (`BypassSandbox: true`).
- **Prisma Schema Drift**:
  If backend queries fail or type errors occur regarding Prisma models, run `npm --prefix backend run prisma:generate`. If PostgreSQL migrations are needed, run `npm --prefix backend run prisma:migrate`.
- **Contract Drift (`sync:shared:check` fails)**:
  Run `make sync-shared`. Remember: edit in `backend/src/shared/`, never in `frontend/src/shared/`.
- **WebSocket Ticket Rejected / 401**:
  WebSocket handshakes require an ephemeral ticket acquired via `POST /v1/boards/:id/ws-ticket`. Tickets expire after 30 seconds.
- **Detached HEAD in Submodules**:
  Ensure submodules are on branch `main`: `git -C frontend checkout main && git -C backend checkout main`.
